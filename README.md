# RaiZo Tools

RaiZo Tools — Windows-приложение для локальной разработки и администрирования
DayZ. Оно объединяет запуск сервера и клиента, управление модами и миссиями,
просмотр логов, редактирование `serverDZ.cfg` и сборку PBO.

Целевая платформа — Windows x64. Готовая сборка не требует установленного
Python: скачайте архив со страницы
[последнего релиза](https://github.com/byRaiZo/RaiZo_Tools/releases/latest),
распакуйте его и запустите `RaiZoTools.exe`.

## Возможности

### Запуск DayZ

- запуск и остановка сервера, клиента либо обоих процессов;
- режимы Dedicated и Diag, ветки Stable и Experimental;
- автоматические параметры Diag, включая `-filePatching`;
- отдельные пресеты с портом, IP, миссией, CFG, модами и аргументами запуска;
- выбор существующей миссии и CFG либо создание отдельного CFG из шаблона;
- проверка EXE, CFG, миссии, модов, junction-ссылок, ключей и порта перед стартом;
- безопасный перезапуск только соответствующего процессу пресета;
- подхват уже запущенных процессов после перезапуска RaiZo Tools;
- состояния `запускается`, `запущен`, `выключается`, `остановлен` и `сбой`;
- мягкая остановка через `WM_CLOSE` с принудительным завершением по тайм-ауту;
- автоматическая остановка процесса, если запуск сорван ошибкой DayZ;
- скрытие внешнего окна сервера с сохранением живой консоли внутри приложения;
- очистка логов перед запуском только при включённой настройке;
- отдельная подтверждаемая команда вайпа `storage_*` выбранной миссии;
- системный трей и компактное окно управления.

При запуске Dedicated параметры `filePatching` не передаются. Для Diag нужные
параметры включаются автоматически. Выбранная миссия синхронизируется с
параметром `template` в CFG перед стартом.

### Моды

- поиск модов в Steam Workshop, каталогах DayZ и DayZ Server;
- добавление внешних локальных модов;
- фильтрация, сортировка, пользовательские флаги и группы;
- назначение client/server-only и управление порядком загрузки;
- зависимости Steam-модов и ручные зависимости локальных модов;
- списки сорсов для автоматической перепаковки изменённых модов;
- подключение выбранных модов к пресету вместе с зависимостями;
- копирование публичных `.bikey` в `DayZServer\keys` без удаления существующих
  ключей;
- проверка обновлений Workshop-модов.

Общая библиотека находится в `DayZServer\MODS`. RaiZo Tools создаёт в ней NTFS
junction-ссылки на Steam и локальные моды: содержимое исходных папок не
копируется и не изменяется. При конфликте с настоящей папкой или чужой ссылкой
программа останавливает операцию и показывает ошибку.

### Логи и консоль

- отдельный выбор источника: сервер или клиент;
- Script-лог по умолчанию, RPT и ADM открываются только по запросу;
- автоматический выбор самого нового файла каждого типа;
- режим просмотра последнего файла или всех найденных файлов;
- чтение новых строк в реальном времени и обработка ротации;
- пауза, очистка экрана и автопрокрутка;
- обычный текстовый поиск и расширенный regex-фильтр;
- цветовое выделение `TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR` и `FATAL`;
- живая консоль сервера в нижней части страницы запуска с отдельной паузой.

Отслеживается только открытый тип лога, поэтому закрытые RPT/ADM-файлы не
создают лишней нагрузки.

### Конфиг сервера и миссии

- встроенный редактор `serverDZ.cfg`;
- сохранение комментариев и запись UTF-8 без BOM;
- выбор существующего CFG или явное создание нового из шаблона;
- выбор уже установленной миссии;
- загрузка миссий из каталога сразу в `DayZServer\mpmissions`;
- безопасная распаковка ZIP через staging с защитой от Zip Slip и rollback;
- сохранение `storage_*` при обновлении миссии;
- настройка SteamID и прав для COT, VPPAdminTools и LBmaster.

Рабочая структура остаётся обычной для DayZ Server:

```text
DayZServer\
├─ serverDZ*.cfg
├─ profiles\
├─ mpmissions\
├─ MODS\
└─ keys\
```

Скрытые рабочие копии сервера и миссий не создаются. Автоматически создаётся
только папка `MODS`, если её ещё нет.

### PBO Builder

В приложение встроено собственное ядро PBO Builder без Mikero:

- сборка одного или нескольких аддонов;
- отдельные папки вывода client и server;
- предварительная проверка `CfgPatches`, `CfgMods`, ссылок и структуры файлов;
- P3D Binarize через DayZ Tools;
- преобразование `config.cpp` и RVMAT через CfgConvert;
- дополнительная защита P3D через настраиваемый внешний инструмент;
- подпись PBO через DSSignFile и публикация `.bikey`;
- инкрементальный кеш и принудительная полная пересборка;
- staging, безопасная публикация и rollback при ошибке;
- отмена операции, общий журнал сборки и отдельные логи этапов;
- повторная упаковка изменённых модов перед запуском сервера;
- команды CLI и пункт «Собрать PBO» в контекстном меню Windows.

Пути к Binarize, CfgConvert и DSSignFile определяются автоматически, если DayZ
Tools установлен в стандартной библиотеке Steam. Остальные пути можно задать в
настройках PBO Builder. Приватный ключ хранится только как путь к локальному
файлу и не включается в сборку приложения.

### Настройки и обновления

- русский, английский и немецкий интерфейс;
- системная, светлая или тёмная тема;
- выбор поведения крестика: свернуть в трей или полностью закрыть программу;
- автоматический поиск путей DayZ, DayZ Server, Workshop и DayZ Tools;
- настройки остановки процессов, логов, упаковки и Steam Web API;
- фоновая проверка GitHub Releases при запуске;
- однократный показ окна для каждой новой версии;
- загрузка ZIP с проверкой SHA-256 и установка после подтверждения;
- rollback при неудачной установке обновления.

Настройки, журналы приложения, manifest junction-ссылок и загруженное обновление
хранятся в `%LOCALAPPDATA%\RaiZo_Tools`. JSON-файлы настроек сохраняются
атомарно.

## Первый запуск

При первом запуске мастер предлагает найти или выбрать:

1. DayZ Stable и, при наличии, Experimental;
2. DayZ Server;
3. Steam Workshop;
4. DayZ Tools;
5. SteamID64 администраторов.

После мастера создайте пресет, выберите установленную миссию и CFG, подключите
нужные моды и выполните запуск. Существующие конфиги и миссии используются на
месте и не переносятся в отдельный каталог RaiZo Tools.

## Команды сервера и ярлыки

Управлять сохранённым пресетом можно без открытия главного окна:

```powershell
RaiZoTools.exe server start  --preset "Diag" --target server
RaiZoTools.exe server start  --preset "Diag" --target all
RaiZoTools.exe server stop   --preset "Diag" --target client
RaiZoTools.exe server status --preset "Diag" --target all
```

`--target` принимает `server`, `client` или `all`. Ветка берётся из пресета, но
её можно заменить параметром `--branch stable|experimental`.

Кнопка с иконкой ссылки рядом с выбором пресета создаёт `.lnk` для запуска или
остановки. Повторный запуск через ярлык перезапускает уже работающий целевой
процесс. Запущенное через ярлык окно сервера остаётся видимым независимо от
GUI-настройки «Скрыть окно сервера».

## PBO Builder CLI

CLI использует то же ядро, настройки, preflight, кеш и журналирование, что и
встроенная страница PBO Builder. Исходником может быть папка одного аддона либо
корень с несколькими аддонами.

### Форматы запуска

Совместимый с отдельным PBO Builder краткий формат:

```powershell
RaiZoTools.exe -pack "P:\MyAddon" "F:\DayZServer\MODS\@MyMod"
```

Второй аргумент может быть корнем выходного мода либо полным путём к `.pbo`.
Если указан файл `...\Addons\MyAddon.pbo`, CLI автоматически определит корень
мода и имя PBO `MyAddon`.

Расширенный формат:

```powershell
RaiZoTools.exe --pack-folder "P:\MyAddon" `
  --output-root "F:\DayZServer\MODS\@MyMod" `
  --saved-options
```

### Исходники и вывод

| Параметр | Назначение |
| --- | --- |
| `-pack SOURCE OUTPUT` | Краткая команда: папка сорсов и корень выходного мода либо полный путь к PBO. |
| `--pack-folder SOURCE` | Папка одного аддона или корень, содержащий несколько аддонов. Алиас: `-packFolder`. |
| `--output-root PATH` | Корень клиентского выходного мода. PBO записываются в `PATH\Addons`. |
| `--output-server-root PATH` | Отдельный корень для аддонов, назначенных на серверный вывод. |
| `--pbo-name NAME` | Принудительное имя PBO без расширения. Применяется при сборке одного аддона. |
| `--project-root PATH` | Корень проекта DayZ, обычно диск `P:`. Используется для разрешения ссылок и Binarize. |
| `--temp-dir PATH` | Рабочая папка staging, Binarize и промежуточных файлов. |
| `--exclude-patterns LIST` | Маски исключений через запятую, точку с запятой или новую строку, например `*.psd,source,*.bak`. |

Для `--pack-folder` выход обязателен: задайте `--output-root` либо один раз
выберите папку вывода в GUI и используйте `--saved-options`.

### Этапы сборки

| Параметр | Назначение |
| --- | --- |
| `--preflight` | Проверить структуру, конфиги, модели и ссылки перед упаковкой. Алиас: `-preflight`. |
| `--binarize-p3d` | Бинаризовать исходные MLOD P3D через DayZ Binarize. Алиас: `-binarizeP3D`. |
| `--cpp-rvmat-to-bin` | Преобразовать `config.cpp` и RVMAT через CfgConvert. Алиас: `-cppRvmatToBin`. |
| `--protect-p3d` | Запустить настроенную защиту уже бинаризованных P3D. Алиас: `-protectP3D`. |
| `--sign-pbo` | Подписать готовые PBO через DSSignFile и скопировать соответствующий `.bikey`. Алиас: `-signPBO`. |
| `--force-rebuild` | Не использовать результат инкрементального кеша и полностью пересобрать выбранные аддоны. Алиас: `-forceRebuild`. |
| `--saved-options` | Взять значения этапов сборки и сохранённые пути из настроек GUI. Явные CLI-флаги имеют приоритет. |
| `--max-processes N` | Максимальное число параллельных процессов, от 1 до 64. |

Без `--saved-options` необъявленные этапы выключены. Для явного отключения
сохранённой настройки доступны `--no-preflight`, `--no-binarize`,
`--no-convert`, `--no-protect`, `--no-sign` и `--no-force-rebuild`.

### Пути внешних инструментов

| Параметр | Назначение |
| --- | --- |
| `--binarize-exe PATH` | Полный путь к `binarize.exe`. |
| `--cfgconvert-exe PATH` | Полный путь к `CfgConvert.exe`. |
| `--dssignfile-exe PATH` | Полный путь к `DSSignFile.exe`. |
| `--private-key PATH` | Путь к приватному ключу `.biprivatekey` для подписи. |
| `--p3d-obfuscator-exe PATH` | Путь к настраиваемому инструменту защиты P3D. |

Если путь не передан, CLI использует найденный DayZ Tools или сохранённое
значение PBO Builder.

### Примеры

Проверка, бинаризация, CfgConvert и полная пересборка:

```powershell
RaiZoTools.exe -pack "P:\RZ_Weapons" `
  "F:\DayZServer\MODS\@RaiZoClient\Addons\RZ_Weapons.pbo" `
  --preflight --binarize-p3d --cpp-rvmat-to-bin --force-rebuild
```

Подпись с явными путями:

```powershell
RaiZoTools.exe --pack-folder "P:\RZ_Server" `
  --output-root "F:\DayZServer\MODS\@RaiZoServer" `
  --sign-pbo `
  --dssignfile-exe "F:\Steam\steamapps\common\DayZ Tools\Bin\DSUtils\DSSignFile.exe" `
  --private-key "P:\Keys\RaiZo.biprivatekey"
```

Автоматический запуск без ожидания Enter после завершения:

```powershell
RaiZoTools.exe --pack-folder "P:\MyAddon" `
  --output-root "F:\DayZServer\MODS\@MyMod" `
  --saved-options --no-wait
```

Успешная сборка возвращает код `0`, ошибка аргументов, preflight или упаковки —
ненулевой код. Полный журнал сохраняется в каталоге логов RaiZo Tools.

### Справка и контекстное меню

Полный список параметров:

```powershell
RaiZoTools.exe --help
```

Установка и удаление команды «Собрать PBO» в контекстном меню папок Windows
для текущего пользователя:

```powershell
RaiZoTools.exe --install-pbo-context-menu
RaiZoTools.exe --remove-pbo-context-menu
```

## Безопасность данных

- обычный запуск и обновление миссии не удаляют `storage_*`;
- вайп persistence выполняется только отдельной командой после подтверждения;
- очистка логов не затрагивает `MODS`, `mpmissions` и `storage_*`;
- junction-ссылка удаляется только тогда, когда она создана RaiZo Tools;
- настоящие папки модов и исходные файлы не удаляются;
- конфликтующие каталоги и чужие ссылки не заменяются автоматически;
- ZIP миссий и обновлений проверяются до публикации файлов;
- целевые процессы сопоставляются по EXE и аргументам, чтобы не завершать
  посторонние экземпляры DayZ.

## Запуск из исходников

Требуется Python 3.13:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Проверка и сборка релизного ZIP:

```powershell
python -m pip install -r requirements-dev.txt
python -m ruff check .
pyright
python -m pytest -q
python tools/build.py --clean
```

Результат находится в `dist\RaiZo Tools\RaiZoTools.exe`; рядом создаются ZIP и
файл SHA-256. Старые локальные сборки очищаются параметром `--clean`.
